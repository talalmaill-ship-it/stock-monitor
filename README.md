# مراقب الأسهم إلى Telegram — دليل التشغيل

يراقب بالترتيب: **MLP، RCMT، IHT، AWX، ANGH**. هذه أسهم ظهرت في فحص 8 أكتوبر 2026 بحجم تداول يومي غير معتاد وحركة إغلاق صغيرة؛ الاتجاه غير محسوم. الغرض مراقبة فقط.

**الحزمة جاهزة، لكنها لن تعمل حتى ترفع الملفات إلى حسابك وتضيف الأسرار. لا تحتاج تشغيل الكمبيوتر بعدها.**

## 1. أنشئ بوت Telegram

1. افتح البوت الرسمي [BotFather](https://t.me/BotFather).
2. أرسل `/newbot`، ثم اختر اسمًا، ثم اسم مستخدم ينتهي بـ `bot`.
3. سيعطيك BotFather توكن. احتفظ به لنفسك؛ لا تضعه في ملف أو ترسله في المحادثة.
4. افتح رابط بوتك الجديد واضغط **Start**، ثم أرسل له `hello`.
5. للحصول على Chat ID، افتح العنوان التالي في متصفحك، واستبدل `YOUR_BOT_TOKEN` بالتوكن:

   `https://api.telegram.org/botYOUR_BOT_TOKEN/getUpdates`

6. في النتيجة، ابحث عن `message` ثم `chat` ثم `id`. انسخ الرقم، وليس `update_id` أو اسم المستخدم.
7. إذا ظهرت `"result": []`، أرسل رسالة جديدة إلى بوتك وأعد تحميل الصفحة. استخدم بوتًا جديدًا مخصصًا لهذا المشروع لتجنب تعارض webhook مع خدمة أخرى.
8. لا تشارك الرابط بعد استبدال التوكن ولا تصوّره؛ يحتوي سرك. تستطيع إلغاء التوكن وإصدار غيره من BotFather إذا انكشف.

## 2. أنشئ مستودع GitHub وأضف الأسرار

1. افتح [إنشاء مستودع GitHub](https://github.com/new)، وسجّل الدخول.
2. الاسم: `stock-monitor`. اختر **Public** للاستفادة من تشغيل GitHub القياسي المجاني، وفعل **Add a README file**، ثم **Create repository**.
3. كود المشروع والأسهم وملف حالة التنبيهات ستكون علنية. التوكن وChat ID يبقيان في Secrets ولا يحفظهما الكود في المستودع.
4. افتح **Settings → Secrets and variables → Actions → New repository secret**.
5. أضف سرًا باسم `TELEGRAM_BOT_TOKEN` وقيمته توكن BotFather.
6. أضف سرًا آخر باسم `TELEGRAM_CHAT_ID` وقيمته الرقم الذي نسخته.
7. أضف `TWELVE_DATA_API_KEY` بقيمة مفتاح Twelve Data المجاني. مفتاح Alpha Vantage المجاني غير مستخدم لتنبيهات الأسعار داخل اليوم؛ لا تحتاج مفتاحًا ثانيًا.
8. لا تحتاج إنشاء GitHub token يدويًا. GitHub يوفر التوكن المؤقت تلقائيًا للتشغيل.

## 3. أضف الملفات

فك ضغط الحزمة. داخل مجلد `stock-monitor` ستجد كل الملفات كاملة.

من المستودع اختر **Add file → Create new file**، أدخل اسم الملف، وانسخ محتواه، ثم **Commit changes** إلى الفرع الافتراضي `main`. كرر بالترتيب:

| اسم الملف في GitHub | المحتوى من الحزمة |
|---|---|
| `monitor.py` | السكربت الكامل |
| `requirements.txt` | مكتبة البيانات |
| `monitor-state.json` | يبدأ بـ `{"days": {}}` |
| `.github/workflows/monitor.yml` | ملف التشغيل؛ أضفه أخيرًا |

يمكن رفع الملفات الثلاثة الأولى عبر **Add file → Upload files**. لا ترفع ZIP نفسه، ولا تضف مجلد `stock-monitor` كطبقة داخل المستودع. يجب أن يكون `monitor.py` في الصفحة الرئيسية للمستودع.

**لملف التشغيل:** انسخ الاسم `.github/workflows/monitor.yml` كاملًا في خانة الاسم؛ GitHub ينشئ المجلدات تلقائيًا. في لينكس قد يكون مجلد `.github` مخفيًا؛ اضغط `Ctrl+H` بعد فك الضغط لإظهاره.

ملف `test_monitor.py` اختياري؛ يحتوي اختبارات منطق البرنامج ولا يلزم للتشغيل. لا تعدّل أو تمسح `monitor-state.json` بعد بدء المراقبة، لأنه يحفظ التنبيهات السابقة.

## 4. جرّب رسالة Telegram

1. افتح **Actions → Stock Monitor → Run workflow**.
2. اجعل `mode` على **test**، واضغط **Run workflow**.
3. انتظر اكتمال التشغيل بعلامة خضراء. يفترض أن تصلك رسالة: **اختبار الاتصال نجح**.
4. هذا الاختبار يفحص Telegram فقط؛ لا يختلق أسعارًا ولا ينشئ تنبيه حركة.
5. لتجربة جلب الأسعار، نفّذ **Run workflow** مرة أخرى واختر **monitor** أثناء ساعات المراقبة. افتح التشغيل ثم خطوة **Check stocks or send test** لرؤية نتائج الأسهم.
6. وضع `monitor` يطبق الشروط الفعلية: لن يرسل رسالة إن لم توجد حركة تستحق تنبيهًا. خارج الساعات يتوقف دون جلب أسعار. بعد الساعة 20:00 يرسل الملخص إن لم يرسل سابقًا.
7. بعدها التشغيل مجدول تلقائيًا، حتى لو أطفأت الكمبيوتر.

إذا فشل: تحقق من اسمي الأسرار، والتوكن، وChat ID، وأنك ضغطت Start في بوتك. إذا كان الفشل عند حفظ الحالة أو تعطيل التشغيل، تحقق أن إعدادات Actions تسمح بصلاحيات الكتابة؛ الملف يطلب `contents: write` و`actions: write`. قواعد حماية الفرع التي تمنع كتابة البوت ستمنع إرسال التنبيهات، لأن البرنامج يحفظ الحالة قبل الإرسال. استخدم مستودعًا جديدًا مخصصًا لهذا المشروع.

## كيف يعمل التنبيه؟

- فحص مقصود كل 15 دقيقة، من الاثنين إلى الجمعة، بين **04:00 و20:00 بتوقيت نيويورك**، مع ملخص عند أول تشغيل بعد 20:00.
- يستخدم `America/New_York` لحساب التوقيت الصيفي والشتوي. جدول UTC يغطي التوقيتين، ويخرج البرنامج دون طلب بيانات خارج الساعات. لا تعتمد على توقيت جهازك.
- خلال الفترة الحالية، 04:00 نيويورك = 11:00 السعودية، و20:00 نيويورك = 03:00 السعودية في اليوم التالي.
- مقارنة السعر بإغلاق الجلسة العادية السابقة، وليس بإغلاق الساعات الممتدة.
- تنبيه عند +5%، ثم +10%، ثم +15% وهكذا؛ ونفس الشيء عند −5%، ثم −10% وهكذا.
- لا يكرر نفس المستوى والاتجاه والسهم في اليوم نفسه. النزول له سجل منفصل عن الصعود. يبدأ سجل جديد كل يوم بتوقيت نيويورك.
- إذا كانت أول قراءة +12%، يرسل رسالة واحدة بالحركة الفعلية +12% ويعتبر مستويي +5% و+10% مغطّيين. الرجوع إلى +7% لا يرسل رسالة جديدة.
- عند فشل البيانات الصالحة للأسهم الخمسة، يرسل رسالة فشل واحدة فقط في اليوم، ويستمر في المحاولة. الملخص اليومي يبقى رسالة منفصلة، وقد يحتوي `n/a`.
- إذا فشل سهم واحد أو حقل واحد، يظهر `n/a` في السجل والملخص؛ لا يصنع سعرًا بديلًا.
- آخر يوم هو **16 أكتوبر 2026**. بعد ملخص ذلك اليوم يعطّل Workflow تلقائيًا. إذا تعذر تشغيل الملخص، يحاول أول تشغيل بعد الموعد تعطيله دون جلب بيانات. في السعودية يقع ملخص اليوم الأخير تقريبًا الساعة 03:00 صباح **17 أكتوبر**.

شكل الرسالة (قيم توضيحية فقط، ليست أسعارًا فعلية):

```text
تنبيه حركة للمراقبة
SYMBOL | +5.20% | $10.5200
Volume (regular): 123,456 | pre-market
Bid: n/a | Ask: n/a
Quote NY: 2026-10-09 08:30 EDT
Checked NY: 2026-10-09 08:45 EDT
السعر: أحدث قراءة مؤرخة متاحة. Volume: الجلسة العادية فقط.
```

## حدود الحل المجاني — اقرأها مرة واحدة

- **GitHub لا يضمن موعدًا دقيقًا:** قد يتأخر التشغيل عدة دقائق أو أكثر، وقد يسقط تشغيل وقت الضغط. لا يمكن ضمان رصد كل حركة أو إرسال الملخص بالضبط الساعة 20:00.
- **هذا فحص دوري وليس بثًا لحظيًا:** الحركة التي تصل إلى 5% ثم تتراجع بين فحصين قد تفوت. البرنامج يقارن آخر سعر متاح، ولا يفحص كل قمة وقاع داخل الفترة.
- يجرب Twelve Data أولًا خلال الجلسة العادية فقط، بطلبين لكل سهم في الفحص: الإغلاق اليومي السابق وشمعة5 دقائق مؤرخة (نحو260 طلبًا في اليوم قبل الاختبارات اليدوية؛ ينتظر آليًا حتى لا يتجاوز8 طلبات في دقيقة داخل التشغيل). عند غياب المفتاح أو فشل البيانات ينتقل إلى Yahoo. لا يخلط سعر مصدر بإغلاق مصدر آخر. حدود Basic المعلنة 8 اعتمادات بالدقيقة و800 باليوم؛ قد تختلف التغطية أو التأخير حسب السوق والخطة.
- Twelve Data المجاني لا يوفر الساعات الممتدة الحالية؛ الخطة Pro أو أعلى توفرها من 07:00 إلى20:00 نيويورك. في هذا المشروع يعتمد الفحص قبل السوق وبعده على Yahoo إذا توفرت قراءة حديثة.
- Alpha Vantage المجاني محدود بـ25 طلبًا يوميًا؛ الأسعار اللحظية والمتأخرة15 دقيقة للأسهم الأمريكية مدفوعة. لذلك لا يستخدم مفتاحه في هذه النسخة، ولا يبدل بين مفاتيح لتجاوز الحصة.
- يستخدم Yahoo Finance كبديل عبر `yfinance`، دون حساب وسيط أو برنامج يعمل على جهازك. المصدر غير رسمي بالنسبة لمكتبة yfinance وقد يقيّد الطلبات أو يتوقف. لا توجد مدة تأخير موحدة أو ضمان توافر.
- السعر هو **أحدث قراءة مؤرخة بين شمعة 5 دقائق وسعر الجلسة العادية أو الممتدة المتاح**، وليس وعدًا بآخر صفقة لحظية. يطلب بيانات ما قبل السوق وبعده عبر `prepost=True`، لكن التغطية تختلف بين الأسهم.
- يرفض سعرًا من يوم سابق، أو شمعة أقدم من 30 دقيقة. هذه نافذة قبول وليست ضمان أن التأخير 30 دقيقة. في الملخص تقاس الحداثة بالنسبة إلى 20:00، لا وقت وصول التشغيل المتأخر. الأسهم قليلة التداول قد تظهر `n/a` حتى لو كان آخر سعر معروفًا.
- الحجم المعروض هو **حجم الجلسة العادية المتاح في المصدر لذلك اليوم**؛ لا يدّعي جمع حجم ما قبل السوق وبعده. قبل توفر حجم الجلسة العادية يظهر `n/a`. حجم الساعات الممتدة `n/a` بدل اختلاق مجموع ناقص.
- يحاول الحصول على Bid وAsk، لكن يعرضهما فقط إذا توفر وقت مستقل صالح لهما. غالبًا سيظهران `n/a` في Yahoo؛ لا يعرض عرضًا وطلبًا قديمين على أنهما حاليان.
- لا يرسل تنبيهًا إذا تعذر الحصول على سعر حديث وإغلاق مرجعي صالح معًا. عطل المصدر أو عطلة السوق قد ينتجان رسالة فشل بيانات بدل أسعار قديمة.
- يحفظ حجز التنبيه قبل إرساله لمنع التكرار عبر التشغيلات. **لا يوجد ضمان تسليم مرة واحدة بالضبط بين GitHub وTelegram:** إذا انقطع التشغيل بين الحفظ والإرسال، أو انتهت مهلة Telegram بنتيجة مجهولة، قد يفوت تنبيه ولن يعاد تلقائيًا. هذا اختيار متعمد لتجنب الرسائل المكررة؛ راجع التشغيل الأحمر عند حدوث فشل.
- التشغيل القياسي للمستودعات العامة مجاني حسب وثائق GitHub. المستودع الخاص له حصة استخدام؛ لا تفترض أنه غير محدود. لا يستخدم المشروع خدمات مدفوعة أو مفاتيح بيانات مدفوعة.
- اختبارات المنطق محلية ولا تثبت نجاح مصدر الأسعار. الاختبار اليدوي يفحص الاتصال الفعلي؛ علامة GitHub الخضراء وحدها لا تعني وجود أسعار صالحة. اعتماد yfinance يسمح بإصدارات ضمن النطاق المكتوب؛ قد تتغير المكتبة أو خدمة Yahoo مستقبلًا.

## 5. الإيقاف أو الحذف

- إيقاف مؤقت: **Actions → Stock Monitor → قائمة ⋯ → Disable workflow**. يمكنك تفعيله لاحقًا من نفس الصفحة؛ بعد الموعد النهائي سيعطّل نفسه مرة أخرى.
- حذف التشغيل: احذف `.github/workflows/monitor.yml` من المستودع. ألغِ أي تشغيل قيد التنفيذ من Actions أيضًا.
- حذف المشروع بالكامل: **Settings → General → Danger Zone → Delete this repository**.
- لإيقاف وصول البوت أيضًا، ألغِ التوكن عبر BotFather. لا تحذف ملف الحالة وحده؛ ذلك يسمح بتكرار تنبيهات اليوم.

## تحديث فحص البيانات

يستخدم المراقب الآن أيضًا حقول Yahoo المنفصلة `preMarketPrice` و`postMarketPrice` و`regularMarketPrice` مع وقت كل منها، ويختار الأحدث عند صلاحيته. يظل يرفض البيانات القديمة؛ وهذا التعديل لا يضمن أن Yahoo يغطي كل سهم في الساعات الممتدة. أضيف Twelve Data كمصدر مستقل للجلسة العادية مع Yahoo كبديل.

خيار **Run workflow → diagnose** يفحص المصدر ويطبع أوقات البيانات والنتائج في سجل GitHub فقط، دون إرسال Telegram أو تعديل سجل التنبيهات. يمكن تشغيله خارج ساعات المراقبة، فتكون البيانات القديمة `n/a`. إذا ظهرت رسالة انعدام أسعار حديثة، فهي تعني تعذر فحص الحركة وليست تنبيه حركة.

عند تعديل ملفات الكود أو التشغيل، يعمل وضع `diagnose` تلقائيًا: يختبر المنطق ويطبع صلاحية البيانات دون Telegram أو تغيير سجل التنبيهات. خارج الجلسة يجرب مفتاح Twelve Data بطلبين لكل سهم للتشخيص فقط، ويرفض السعر القديم.

- [حدود Twelve Data](https://twelvedata.com/pricing)
- [الساعات الممتدة في Twelve Data](https://support.twelvedata.com/en/articles/5195429-pre-post-market-data)
- [حدود Alpha Vantage](https://www.alphavantage.co/support/)

## الإرسال في الخاص والقروب معًا

أبقِ `TELEGRAM_CHAT_ID` للخاص، وأضف Secret اختياريًا باسم `TELEGRAM_GROUP_CHAT_ID`.

1. أضف البوت إلى القروب واسمح له بإرسال الرسائل. في القروب العادي لا يحتاج مشرفًا إن كانت صلاحية الإرسال متاحة.
2. أرسل `/start@BOT_USERNAME` داخل القروب، واستبدل اسم المستخدم باسم بوتك.
3. افتح عنوان `getUpdates` المذكور أعلاه. ابحث عن `message → chat → id` حيث نوع الدردشة `group` أو `supergroup` واسمها اسم قروبك. انسخ الرقم كاملًا بعلامة السالب.
4. احفظ الرقم في `TELEGRAM_GROUP_CHAT_ID` ثم شغّل وضع `test`. يفترض أن تصل رسالة التجربة إلى الخاص والقروب.
5. بعد ذلك ترسل التنبيهات والملخص ورسالة فشل البيانات إلى الاثنين. حذف السر الاختياري يعيد الإرسال إلى الخاص فقط.

الإرسال يتم بالتتابع. إذا نجح الإرسال للخاص وفشل للقروب، يظهر التشغيل أحمر ولا يعاد التنبيه تلقائيًا لتجنب تكراره في الخاص. راجع صلاحية البوت ومعرف القروب.
